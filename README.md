# 金枢｜金融中后台 Agent 工作台

**查得到依据，算得清结果，改得动流程。**

个人项目 · 产品与方案设计 · AI 辅助工程实现。面向金融资料查询、理财对标、发行排期和周报核查，将知识、确定性工具与人工复核放进一个工作台；不是机构正式上线系统。

## 三分钟了解

| 你要做什么 | 工作台怎样帮助 | 保留什么边界 |
|---|---|---|
| 查一项知识或流程 | 先展示相关原文要点，再展开完整依据和出处 | 要点是原文节选，不冒充模型总结或正式制度 |
| 处理一份业务任务 | 确认输入 → 执行 → 查看异常 → 人工确认 → 导出 | 修改输入使旧结果与确认失效；不执行账户、付款或发行 |
| 改善一次没有解决的问题 | 归因 → 受限候选 → 同批回放 → 人工确认 → 版本复核 | 不训练权重，不自动发布任意代码，不把点击当收益 |

## V7 本轮改了什么

**先改善阅读。** 回答先显示至多两段相关原文要点、下一步操作；完整引用和技术参数折叠保留。业务工具增加友好字段，策略回放用原策略/候选策略分栏，不要求业务人员先读 JSON。

**再使变更可验证。** 网页候选回放使用实际问答入口，不再仅检查“全部旧来源是否保留”。配置、资料、样本、评测代码及基线有指纹，发布前重新核对；当前版本才能回滚，回滚恢复上一个版本而非硬编码参数。

**让结果跟着任务走。** 八类工具共享任务字段和状态；输入、请求、结果与确认绑定版本。迟到结果不能覆盖新任务，生成文件期间改输入也停止旧导出。反馈更新同一次任务，未反馈为未知。

**保护原需求。** 保留原问题，限制新增检索提示，不默改数字、产品编码、日期或否定条件。原模型提示、调用预算、pi 与原引擎不替换；默认检索上限没有全局调大。

## 两种运行方式，不混为一谈

**浏览器轻量版**：BM25、规则路由、原文整理和真实固定工具；默认不调用模型，没有语义 Embedding。资料与反馈存当前浏览器的 IndexedDB；“本地确认”不是企业多用户审批。可选 `/api/answer` 仍需部署者配置模型和访问码、用户明确许可。

**完整服务工程**：保留 `engine/` 与 `jinshu/` 的 FastAPI、MongoDB、Milvus、Redis、模型及 pi 适配。V7 加了改写与发布复核合同；本轮 Python 验收为离线/受控测试，不替代真实数据库、真实模型和多用户部署验收。

> 既有公开站点由独立 `jinshu-workbench` 发布仓库固定上游版本。主仓库更新不等于站点已更新。实际运行版本以站点 `build-info.json`、发布记录及验收报告为准；不要将历史 V6 实站成绩改称 V7 成绩。

## 本机打开轻量工作台

```bash
cd lite
npm ci --ignore-scripts
npm test
npm run build
python -m http.server 8795 --directory dist
```

浏览器访问 `http://localhost:8795`。纯静态服务不提供可选模型 API。完整服务仍按 [V4 指南](docs/V4_GUIDE.md) 配置；更新前保留本机 `.env` 与业务数据，不使用 `down -v` 清除持久数据。

## 验收怎样读

保留原 500 项标签：300 道问答、100 项工具、60 项证据状态、40 项旧 Loop 函数合同。本轮本地复测为 **489/500**：问答289/300、工具100/100、证据60/60、旧Loop40/40；11项问答仍保留。新治理和任务测试单独记录，不把不同检查合并为模型准确率。

```bash
python evaluation/build_questions.py
python evaluation/build_toolcases.py
node evaluation/run500_v7.mjs
PYTHONPATH=engine/backend:. pytest -q
```

本轮增加真实界面浏览器验收脚本；CI结果、跳过项、失败记录和环境见 `evidence/v7/` 与 Actions。受控模型接口测试不发付费请求。没有新用户试点、真实订单、线上A/B或金融业务提效成绩。
