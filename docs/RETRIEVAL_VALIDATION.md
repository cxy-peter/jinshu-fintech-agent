# 资料检索修复与验证边界

本记录对应 2026-11-06 的 V11 后续改进。问题定位在资料入口、查询表达、正文切片、候选筛选和索引加载；没有更换基础模型，没有把参考项目的测试成绩转写为金枢成绩。

## 改动

1. 浏览器个人资料、即时上传和服务器参考库使用同一份词项写法表。统一全角字符、英文缩写与中文名称；例如 FOF、Fund of Funds、基金中基金进入同一个检索词项。词表只帮助找原文，不提供预制答案。
2. 将“请解释、根据资料、注明页码”等提问格式与检索主题分开。匹配到多个别名时只按一个概念计入覆盖分母；产品或交易标识不得按缩写子串模糊匹配。
3. 只有明确追问才补入最近用户问题的主题。历史模型回答不作为新证据；改问一个明确的新主题时，不强行沿用上题。
4. 文档名称不能使每页都成为有关证据。检索以正文及其实际章节为依据，识别整页目录，排除重复页脚；完整原文仍保留供阅读回查。标题相近但主题不同的“功能/职能”段落会进一步核对标题主体。
5. 保留原文页码、切片标识和正文哈希。结果中的词项覆盖是检索相关性提示，不是模型置信度，更不表示答案已经验证正确。
6. 共享参考库的派生倒排索引可以压缩后保存为独立记录。键包含原档版本和检索实现/词表版本；冷实例可加载预计算索引，旧档案无需迁移。坏索引回退重建；派生索引写入失败会显示退化为内存索引，不修改原档。
7. MongoDB 客户端按事件循环复用连接。权限、资料当前版本和发布头仍逐次检查，不用缓存绕过权限或旧版本失效。

### 参考库诊断接口

`GET /api/library/reference-search?q=...` 仍要求登录，不调用生成模型。响应包含 `sources`、`mode`、`diagnostics` 和 `model_called=false`。诊断会区分未导入、空索引、无命中和已有命中，并记录：

- `indexed_documents`、`indexed_chunks`：当前索引规模；
- `query_focus`、`matched_aliases`：实际检索主题及使用的写法映射；
- `index_mode`：内存命中、已保存索引加载或原档重建；
- `index_load_ms`、`retrieval_ms`、`total_ms`：服务器内部不同阶段用时。

接口的总耗时还可能包含鉴权、网络和数据库访问。问答还要经过生成模型。不能把本机几毫秒的词项检索说成整个在线回答保证三秒，也不能以一次快请求代替延迟分布或压测。

## 可复现的回归样本

固定输入为 [retrieval_diagnostics.json](../tests/fixtures/retrieval_diagnostics.json)：9 份人工合成资料、16 个问题，含缩写、全角、中英文、长问题、追问、换题、正文无关但标题匹配、未知产品代码和无关问题。全部是针对已发现问题设计的诊断用例；不是随机抽样或独立评测集。

对照基线为 `c367459168a9791ae279a5991e19039608932b8d`。同一组用例中，基线 4/16 满足“应命中题首位来源正确、应拒绝题无来源”；改进后 16/16 满足该条件。详细原始输入、返回文档/页码及测量值见 [原始对照记录](validation/retrieval-diagnostics-20261106.json)。该数字仅说明这些回归缺陷得到修复，不能写为 RAG 总体准确率、真实用户解决率或模型准确率。

```bash
python scripts/evaluate_retrieval.py --output /tmp/jinshu-retrieval-current.json
python -m pytest -q tests/core/test_retrieval.py tests/core/test_references.py tests/core/test_governed.py
node --test tests/personal_materials.test.mjs
```

如需重新执行旧代码对照，可创建指定基线的只读工作树，再将同一脚本指向该目录：

```bash
git worktree add --detach /tmp/jinshu-retrieval-baseline c367459168a9791ae279a5991e19039608932b8d
python scripts/evaluate_retrieval.py --code-root /tmp/jinshu-retrieval-baseline --output /tmp/jinshu-retrieval-baseline.json
```

脚本不调用语言模型，也不包含用户上传的教材或报告正文。旧版本没有新查询准备模块时，脚本使用该版本已有的追问拼接规则，避免把完全没有多轮上下文的运行冒充旧系统表现。

## 仍需分开验证

词项改写不能修复扫描件无文字层、错误 OCR、缺少原文、权限不可用或跨页表格丢列。未识别的新写法仍可能漏召回；广义语义检索、交叉编码器重排和独立人审评测应另行记录。共享学习库采用本节描述的页级词项检索；已有受审制度库可按配置使用 BGE 语义候选，二者不能混写成每次请求都运行完整向量/Reranker 链路。

词项写法表中的金融缩写链接至相应官方术语来源；“发行数量/发行支数、存续金额/存续规模”等是本项目的业务字段写法映射，不代表任何机构规则。原始资料的授权、有效期和来源权威仍需各自管理。
