# V11.1：统一工作台、个人知识库与业务复现

本文说明本次源码改动，不把本地测试、线上部署和真实业务效果混为一谈。具体发布提交、部署 ID 与实测结果另见 `V11_1_RELEASE.md`。V11 原有检查点、独立复核与反馈灰度机制继续使用。

## 一、以什么作为事实基准

主仓库是 `cxy-peter/jinshu-fintech-agent`，默认入口为 `index.py → core.app`，正式项目是 Vercel `jinshu-workbench`。原 `jinshu-workbench` 仓库保留历史，不再作为第二套线上实现。

本轮逐项阅读了公开交接目录及其引用的 V11 架构、发布、简历和面试文件，并比对旧工作台的检索、文件解析、浏览器存储和回答服务。旧版已有的浏览器个人资料恢复、8 类计算工具和 V11 审核流程不重复重建。新增能力接到同一套 FastAPI 和网页。

升级前线上应用提交为 `fe3eb3261cd7feda9dc2e5c55b52e622009041ab`，GitHub 文档主分支为 `c367459168a9791ae279a5991e19039608932b8d`。两者的差异主要包括交接资料，不能仅用网页版本号推断源码是否同步。

升级前已登录的共享资料目录共有 93 份、3790 页；按文件名检查没有找到“黄达”“金融学”或本轮上银报告。这证明当时的服务器共享目录没有这两份文件，不能推断用户旧浏览器 IndexedDB 也没有，更不能编造文件丢失原因。

## 二、个人文件在网页上如何使用

“资料与上传 → 我的云端资料”支持 PDF、DOCX、TXT、MD、CSV、JSON。选择单个文件或整个文件夹后，通过有界分片上传、SHA256 完整性检查、原生正文提取和索引建立完成导入。相同浏览器再次导入同一内容会跳过重复。当前原型每份 12MB、每浏览器 25 份；原文件、索引和正文存放于独立资料记录，不塞入原有 8MB 业务状态正文。

个人资料归浏览器的不可猜测 HttpOnly 身份所有，公共演示账号不会因此获得阅读权。刷新后仍可使用；换浏览器、换设备时可生成 24 小时单次认领链接，认领成功会转移资料所有权。链接中的凭据仅放在 URL fragment，处理时移除；它是临时访问凭据，不能提交 GitHub 或公开分享。此方式是个人演示版的访问控制，尚不是企业 SSO、组织账号生命周期或完整的设备恢复体系。

选择“依据资料回答”后，关键定义、金额、日期和业务规则需有本轮原文支持。没有相关片段时返回知识缺口，不调用模型补写机构事实。也可主动选择“一般知识解释”，但结果会明确区分没有检索依据的解释。

在原文窗口可下载经身份校验的原文件，方便核对复杂表格。

“只检索原文”不调用 DeepSeek，无需模型授权勾选。它显示服务端检索耗时、浏览器请求往返耗时、文件名和提取正文。“发送问题”先通过 SSE 返回检索片段，再返回经引用编号检查的完整回答。这里的 SSE 是**检索进度和最终回答**，不是已实现模型 token 逐字输出；两者的时延不可混写。

PDF 使用物理文件页码。Word 和普通文本显示“文本段”，不虚构排版页码。扫描 PDF 无正文会报错或显示 OCR 缺页提示，不把空页当已识别。复杂表格的金额和列对应仍须对照原文件。

## 三、本地文件夹与线上使用的关系

默认目标为 Windows `F:\JinshuData`，允许用户更换。浏览器网页不能未经授权遍历用户电脑的 F 盘。线上直接使用“选择文件夹并上传”即可；文件选择授权仅覆盖本次选中的文件，不会变成无限制后台监控。

本机启动器提供同一个工作台及指定根目录的增量索引。扫描读取允许的文件类型，按内容变化更新索引，删除文件后撤销旧证据；提问只查已建立索引，避免每次遍历整盘。目录配置与扫描和聊天分离，便于定位文件未扫描、正文为空、格式不支持等情况。

本机文件夹接口限制为 loopback 主机和本机连接；Vercel 上禁用直接磁盘访问。不会把任意 HTTP 参数解释为服务器文件路径，也不通过软链接越过授权根目录。服务器环境不把 `F:\...` 当成真实 Windows 磁盘。

## 四、召回改进与实际边界

| 改动 | 解决的问题 | 不代表什么 |
|---|---|---|
| 前后端共用术语表、NFKC 归一化 | FOF / 基金中基金、全角字符、中文别名在不同入口行为不一致 | 不把词典解释伪装为文档原文 |
| 清理提问套话，显式追问只补最近用户主题 | 问法变化、旧回答污染新问题 | 不把任意历史回答当事实 |
| 正文证据门控与产品标识检查 | 文档标题有关、正文无关仍被召回 | 不是事实正确性证明 |
| 整页目录识别、定义段和业务字段排序 | 目录抢占正文、报告字段词形不一致 | 不承诺所有复杂表格都已结构化 |
| BM25 倒排预计算、索引版本绑定 | 冷请求反复切片和分词 | 不是每轮重新嵌入所有文档 |
| Mongo 连接按进程事件循环复用 | 每次请求重新连接的额外开销 | 不消除跨地区网络时延 |
| 检索先展示，生成后展示 | 用户只能等整段模型答案才知道有无证据 | 不等于完整答案 3 秒 SLA |

已经审核的共享机构条款继续使用原有 BM25 + CPU BGE、RRF 和条款覆盖重排，可选 Milvus/模型重排。历史学习参考、云端个人资料和本机文件夹使用本轮的页级 BM25、术语归一化和正文门控。**不能把所有资料入口都写成已经接入向量库或 Reranker 模型。**

更大语料、跨概念同义改写仍需要中文向量召回与轻量 reranker，并用保留测试集验证收益。离线切片/建索引是导入阶段的必要工作，不能单靠“切得更碎”解决缺文档、权限、OCR、表头和问题理解问题。

3 秒的目标应定义为“索引就绪后的问题请求 → 返回可核对证据”。同时记录服务端检索耗时和浏览器往返时间；冷实例、网络地区和并发可能影响尾延迟。完整回答还包括 DeepSeek 生成时间，不应由 Flash 名称推导出时延保证。模型默认关闭思考模式，候选重排默认不用额外模型调用。

## 五、业务理解如何进入可复现流程

工具的输入字段、业务意义、边界、原始代码来源和可复现问题由业务能力目录维护。网页可主动载入依据国务院通知整理的2026年中国放假调休日历，保留来源和年度覆盖范围；该日历不是交易所或机构专用日历，也不外推2027年。自然语言建议只能定位已存在的工具并提取明确参数；缺失的日历、产品、区间、数据表必须显式补充，不能用合成数据暗中代替真实输入。

知识回答负责解释制度和口径；金额、排期、可比产品筛选和报表校验由确定性工具执行；任务执行和独立复核由原 V11 流程保存。这保持“资料 → 条件 → 执行 → 修改后重算 → 复核 → 导出”的业务关联，而不是增加互不相关的聊天页面。

参照文旅活动运营赛题的连续流程思想，可以用明确标注的金融合成数据演示资源/日期冲突、条件变更、局部重算和复核交付。文旅赛题样本、课程参考实现以及他人项目的指标不构成金枢的真实生产成果。

## 六、国内与海外部署选择

**当前沿用：Vercel + 已连接 MongoDB + DeepSeek Flash。** 保留现有域名、代码入口和持久数据，适合先验证个人工作台。模型凭据始终在服务端。云端个人资料需要 Mongo 或本地 SQLite 支持的独立资料存储；旧私有 Blob 状态兼容并不自动代表大文档上传也兼容。

**国内常驻后端：阿里云 ECS/腾讯云 CVM 等 + 同地区数据库/对象存储 + CPU 检索服务 + DeepSeek。** 这是针对主要中国大陆使用者的建议架构，并非本次已购买或部署。常驻进程可保温索引，原生 PDF/OCR 和大文件处理可独立排队，资料与索引可放同地区，通常更容易控制跨区往返。不能在未实测和选规格前给固定成本或 3 秒承诺。

**国内托管 RAG：阿里云百炼知识库。** 官方文档提供关键词/向量混合、OCR/结构恢复、多种切片和元数据过滤。可让金枢负责身份、流程、工具和审核，托管平台负责解析/索引/召回；需要通过真实问题集比较召回和费用，不等于一键迁移后所有质量问题自动解决。

**海外 Cloudflare：Workers + R2 + Vectorize，或 Cloudflare 只做入口。** 官方 Vectorize 可保存向量，并关联 R2/D1 中的资料。全部迁移需要新的 Workers 接入和存储适配；不会仅加一层 CDN 就解决当前检索逻辑、权限或缺失文件。若使用 Cloudflare Tunnel 连接本机服务，本机必须持续开机联网，且要单独配置访问认证，不适合作为电脑关机后仍可用的正式后端。

## 七、简历与面试口径

可以描述：对既有金融中后台工具补充可恢复流程、基于资料的引用回答、个人文件导入、增量索引和可复现验收；能讲清代码、失败场景和实际部署记录。

不能描述：课程项目的 489/500 为本轮准确率；合成案例为真实机构效率收益；只有协议模拟就称真实模型调用；未部署的 Milvus/Redis/K8s/HPA 为当前生产能力；词典或规则反馈更新为模型训练、自主修改权重；未真实发生的两人协作或个人实习经历。

测试通过数、检索样本命中率、模型引用合法率、答案事实正确率、用户解决率是不同指标。本轮先公布可复现样本与逐项验收，不用一个“命中率”掩盖测试范围。
