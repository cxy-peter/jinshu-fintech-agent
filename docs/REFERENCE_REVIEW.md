# 参考工程阅读与采用范围

本轮阅读了 GitHub 交接目录、旧工作台和业务 Notebook，以及本次提供的文枢、商旅、文旅资料。这里记录机制来源和采用范围，不把参考项目成绩当作金枢成果。

## 交接材料定位

附件中没有找到准确名为 `01_完整交接Prompt.md`、`03_历史文件与版本索引.md` 的文件。已经使用最新 GitHub 的 `docs/handoff/README.md`、`V11_FULL_CONTEXT.md`、`HISTORY_INDEX.md` 和其引用的架构、发布、简历、面试文件恢复背景。RAR 中是商旅 `shanglv_new` 工程，不是金枢历史交付包。两份新 PDF 则作为个人知识资料导入，不进入公开源码。

## 机制与实现的对应

| 资料 | 采用的思路 | 金枢本轮对应 |
|---|---|---|
| 文枢参考工程 | 可信来源、标题/物理页定位、词项变体、混合检索、Memory预算、候选回放与复核 | 统一前后端查询准备、正文证据门控、页码原文、持久预计算索引；保持原有知识审核与受控反馈 Loop |
| 商旅 V2 | 任务依赖、条件变化使步骤失效、局部重算、请求防重 | 继续使用既有 V11 快照、节点检查点、租约与独立复核；没有再次重写同一流程 |
| [餐饮系统 llx_ordertable](https://github.com/cxy-peter/llx_ordertable) | 服务端决定角色与数据类别；模拟记录隔离；条件改变后重新确认 | 业务计算与审核由后端判断；明确合成输入；修订后旧审批失效；前端选择不授予权限 |
| [MSX-Hackathon-Demo](https://github.com/cxy-peter/MSX-Hackathon-Demo) | 区分已持久化和临时内存；部署状态对使用者透明 | 页面显示实际持久化方式；文件必须在私有资料记录中可回读，不用函数临时目录冒充云数据库 |
| [原业务 Notebook](https://github.com/cxy-peter/Intern-Python4WealthProduct) | 排期、参数转材料、同口径产品比较、数字清洗、邮件记录等业务语义 | 八类已登记工具目录、明确参数提取、严格发送日计划、排期与材料共享输入；具体对应见 BUSINESS_CAPABILITIES.md |
| 文旅运营赛题与数据包 | 活动/资源/日历ID关联；约束冲突；改变条件后重算；成果附件；人工复核 | 金融合成排期案例和既有周报质检/同业对标复核包，保持连续流程 |

文旅数据包包含公开材料和模拟数据。其预算、客流、价格、容量、资源状态及样例效果不能作为真实金融或文旅业务事实；空值和待核验不等于零。原赛题要求面向内部运营、基于资料解释依据、保留人工审核，本项目采用这些结构思想，不宣称参与比赛、通过平台评审或取得业务合作。

## 没有复制或承诺的部分

参考课程压缩包未发现明确再分发许可。本轮独立实现必要机制，没有将原始压缩包、课程源码或用户全文资料公开上传。原工程出现 Milvus、Redis Stream、K8s/HPA、Prometheus、pi Runtime 等不代表当前站点全部启用；状态以实际服务与执行记录为准。

参考材料中的文档数、切片数、Recall/MRR、引用率、时延、吞吐或 Pod 扩容数字均未移入金枢成绩。本轮自己的合成回归、真实 PDF 少量问题、真实线上调用和浏览器操作分别记录。反馈更新是检索/输出策略治理，不是训练模型权重。

## 主仓库与旧工作台如何统一

正式地址始终为 https://jinshu-workbench.vercel.app/ ，源码入口为主仓库的 `index.py → core.app`。旧 `jinshu-workbench` 的浏览器资料恢复与原文阅读能力已在这个工作台接续，V11.1 又增加服务器个人资料及可配置本地目录。所有新接口、网页和业务目录均在主仓库；旧仓库保留历史，不另起一个内容不同的“新版网站”。

旧浏览器 IndexedDB 受同源限制；相同域名可尝试恢复，其他域名的备份需手动导出/导入。新云端个人资料使用独立身份和单次认领，不向所有演示账号公开。
