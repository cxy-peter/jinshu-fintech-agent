# V5.1｜全文阅读、跨页完整性与交付说明

## 本次解决的问题

在用户自己的115页金融学习笔记上，用原生文字提取结果测试同一套网页JS索引，发现“商业银行的职能”容易先命中目录第2页，而不是正文第24页；第四项说明又延续到第25页。只展示排名第一的单片段会造成“检索命中但信息不完整”。

修正包含四点：

1. 对包含多条点线及页码的目录页降权，而不是删除目录。查询明确要求目录时不降权。
2. 对匹配问题核心词的短正文标题加权，减少目录和普通提及压过定义段的情况。
3. 排序完成后，为命中片段增加同文档、有效状态且相距不超过一页的邻片段；最多前一片与后两片。单独记录source_chunk_ids和source_pages，不把上下文扩展算成额外top-k命中。
4. 处理“那怎么办”等短追问时，证据检查使用上一轮主题与本轮原话，避免只有代词而误报无证据。

这是词项检索与有界上下文扩展，不是语义Embedding或模型生成，也不保证所有PDF表格和跨页段落均被正确恢复。

## 实际诊断

私有笔记115页、原生提取186,073字符，网页切片器形成370片，末页115保留。目录降权后，上述问题第一条回到正文24页，邻块证据纳入25页的续文。原文、全文JSON与包含正文的诊断不进入公共仓库。

本人可在网页“资料与上传”导入随交付提供的分页JSON，确认后本地启用；文件保存在本人浏览器，不共享给其他访客。公开网站内置56个重新整理的金融主题，不宣称它们是上传笔记全文。

新增5条功能测试：目录与正文排序、短追问、跨页扩展、无效邻片排除、目录原文保留。合计43条Node测试已通过；GitHub Chromium实际执行了问答、TXT/Word/PDF上传、刷新保留、模拟115页导入、8类工具、Word导出、反馈回放与回滚、移动端布局。

第一次V5.1运行35400710389中，程序测试和浏览器测试均成功，但随后提交测试证据时因工作区还有生成文件而失败。该失败不隐藏；修正CI的证据提交后再次执行。具体最后运行结论以Actions和evidence/v5_1为准。

真实笔记诊断采用PyMuPDF原生提取后运行同一JS切片与检索代码，不是浏览器PDF.js整本真实笔记上传测试。Chromium中的PDF和115页JSON是合成测试样例。43条和16条开发查询不是独立金融准确率；当前没有真人效果评估。
