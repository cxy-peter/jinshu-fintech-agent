# V7 架构与迁移说明

## 保留主干，不整体换框架

原 `engine/`、pi 运行 overlay 与模型 API 提示/预算保留。本轮没有新建另一套金融知识或模型框架；改动集中在 `lite/web/` 和 `jinshu/` 适配层。旅游项目迁移的是问题定位和治理机制，不迁移其城市资料、库存假设、测试数字或技术栈。

## 真实执行链路

浏览器：问题与历史上下文 → 规则路由/手选任务 → 保留原问题的受限提示 → BM25 → 有界证据补全 → 来源身份/原文检查 → 节选、全文、下一步。可选模型接口是独立明确同意分支；网页并未使用Milvus。

工具：Task输入版本 → 确定性执行 → 返回结果或缺失状态 → 结果哈希 → 当前版人工确认 → 文件准备 → 再核对任务版本 → 导出。状态在IndexedDB，运行中的页面刷新标记中断，需要重新执行；不是后台作业自动恢复。

治理：反馈归因 → 受限候选 → 实际问答入口的同批评测 → 人工阅读配对结果 → 发布前配置/语料/样本/评测器/基线复核 → 本地生效 → 恢复前版。发布和业务结果确认是不同记录。

## 三类结构化合同

| 对象 | 本轮落实 | 不扩大解释 |
|---|---|---|
| Task | taskId、flow、params、input/requestVersion、状态、输入/结果哈希、审批、导出 | 八类单工具共享生命周期；没有新增通用多步TaskPlan调度器 |
| Evidence | 原有doc/chunk/version/page/quote身份校验，节选仍属于原文 | 没有新增完整金融结论蕴含证明或历史制度as-of查询 |
| Policy | 候选配置、基线、来源/样本/评测器哈希、配对结果、人工确认与前版恢复 | 本地治理不等于服务器RBAC或在线A/B |

## 完整服务改动

`rewrite_contract.py` 放在改写节点后保留原需求并记录候选检查；`release_contract.py` 把资料、样本、候选及评测代码绑定，`loop.py` 审批前复核与重跑。保留原灰度/回滚实现。当前复核不是多进程数据库事务；单运行时测试不能证明并发发布原子性。

## 故障与退出

无依据不编造；工具缺必要数字不当0；访问码/未授权模型保持原边界；模型超时、错误或旧请求不覆盖当前回答。资料变化必须重新验收；基线变动需重新提出候选；只回滚当前版本。

## 为什么不全局增加top-k

旧300题对照显示top-k5→8仅增加2道通过，而引用字符量增加50.4%。所以本轮保持默认5，扩召回或精简作为有界候选；没有把字符量改称Token费用或真实延迟。改写保护是词项防线，不是任意语义改写绝对安全的证明。
