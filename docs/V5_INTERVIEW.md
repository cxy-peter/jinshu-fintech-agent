# 金枢｜产品面试叙事与关键追问 V5

本页是公开速查版。完整交付文档包含36题，按“思路—回答—追问—实现依据”展开；项目原型、V4服务证据与参考材料示例成绩分开。

## 一分钟介绍

金枢是基于金融实习场景延伸的个人智能助手项目，把资料查询、理财对标、发行排期、报表与核查放到统一工作台。不是从头重写所有工具，而是基于参考Agent工程和已有Python方法做适配，在AI辅助下形成需求、功能、原型和验证材料。重点是明确输入输出、人工复核点、来源与执行记录，再通过反馈和回放检查策略有没有真正影响下一次执行。

## 两条深挖主线

**工具产品化**：已有方法分散 → 定义11类任务和8类计算工具 → 参数/口径/异常规格 → 表格与材料导出 → 反思统一入口不能掩盖业务口径差异。

**可追溯知识与迭代**：跨页和历史资料难完整回答 → 保留页码、全文、资料状态 → 原话/改写/来源/Trace分开 → 反馈生成受限候选 → 实际回放启用回滚 → 反思行为变化不等于业务质量提升。

## 关键问题：先思路再回答

### 1. 怎么识别AI场景？
思路：区分非结构化理解与确定性规则。回答：数字、日期和CSV由程序算；模型用于理解与组织，不让模型代替可测试的计算。先交付查询和草稿，不自动付款或冻结。

### 2. 怎么把需求变成PRD？
思路：角色—触发—输入—规则—输出—例外—验收。回答：以排期为例，约定日期、期限、频率和日历版本；显示原日期、调整结果和原因，异常参数明确报错。完整规格见PRODUCT_SPEC_V5.md。

### 3. 自动路由是什么实现？
思路：规则与学习模型要区分。回答：轻量版使用术语与词项检索结果，短追问沿用上下文，未明确则澄清或手选。分数不是模型概率，没有训练路由分类器。

### 4. 分词和BM25做了什么？
思路：词项、频次、长度与区分度。回答：中文分词加双字补充，BM25包含词频饱和、IDF和长度归一化；k1=1.2，b=0.75，标题另加权。默认没有语义向量或生成模型。

### 5. 怎样保证完整信息能找到？
思路：区分片段预览与全文保存。回答：完整提取文字按页查看，可导出；公开56主题与本人115页笔记导入是不同材料范围。商业银行第四职能跨24—25页，必须检查跨页完整性。

### 6. Embedding与Reranker？
思路：全库召回与少量精排。回答：前者独立编码，后者问题和候选成对判断。V4实际调用BGE512和reranker-base，轻量版不冒充这条链路。BGE-M3不是同名Reranker。

### 7. 为什么索引结果回Mongo？
思路：索引是候选、有效版本是事实状态。回答：查文档active、版本、来源与范围后再用正文；当前完整版是回查后重排，不能照搬参考中不同顺序。

### 8. Harness和DAG的价值？
思路：谁有权决定下一步。回答：流程、预算、参数、工具和失败路径由程序控制，模型只在允许节点推理。固定任务优先固定流程，需要多跳时再增加受限子循环。

### 9. Skill是不是提示词？
思路：输入输出与真实执行。回答：Skill封装任务、参数、约束、计算和错误提示；既有脚本被复用，不是换个名字。网页是等价JS工具，Python留在完整工程，不声称浏览器直接跑Python。

### 10. Memory为什么分层？
思路：不仅存多久，还要看用途和权威。回答：工作、情景、用户偏好、组织知识、程序策略分开。摘要和推断不能变成事实。轻量版是本地逻辑分区，不是已部署Redis服务。

### 11. 自进化怎么证明？
思路：看下一次执行参数。回答：反馈关联Trace、生成受限候选、历史检索回放、本地确认，再观察top-k从5到8；回滚后回基线。证明行为发生变化，不是模型训练或金融准确率提升。

### 12. 知识缺口与检索错误？
思路：有资料但没找到，和根本没有资料不同。回答：intent修路由，retrieval查切片召回，generation查上下文输出，knowledge_gap补资料。轻量版归因由用户选择与规则完成，未冒充LLM反思。

### 13. 哪些指标可报？
思路：分阶段、讲分母。回答：38条程序测试和实际浏览器流程通过；16题是自编单预期来源开发回归。Recall、Hit和MRR不同；引用编号检查、HTTP200和文本重合都不等于语义正确。

### 14. Vercel与完整部署？
思路：展示、计算、持久化分开。回答：默认浏览器检索和工具，上传存在本地IndexedDB；可选API由服务端配置模型并征求发送许可。企业共享资料和长期Worker用Compose。没有完成Vercel账号首次授权前不猜域名。

### 15. 原项目和你自己的贡献？
思路：诚实讲复用与适配。回答：原engine、DAG和Loop思想保留；个人实践聚焦金融任务、数据与工具口径、原型交互、证据展示、操作与验收。AI辅助与参考工程应明确，不虚构学校合作或队友分工。

### 16. 如何符合数字化产品岗位？
思路：需求—方案—原型—验证—反馈。回答：用金融业务理解和数据能力拆问题，形成PRD、规格和验收口径，再用可操作工作台验证。未用过的Axure/Figma不写熟练；可以展示实际原型和流程文档。

## 必须纠正的参考表述
