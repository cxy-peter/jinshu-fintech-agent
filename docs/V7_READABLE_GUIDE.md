# 金枢 V7｜从业务问题到可交付结果

## 为什么做

金融中后台的资料查询、对标计算、排期与周报质检往往分散。金枢把“查资料”和“做计算”分开处理，再通过同一个工作台汇合；原文仍可回查，计算仍由固定工具完成，输出仍需使用者复核。

## 这次优先解决的三个问题

### 1. 有出处，却不好读

旧界面一次显示大量原文和执行参数。V7 先展示与本轮问题相关的原文节选、来源和下一步；完整原文、位置与执行参数折叠保留。节选不是新生成的结论，必要条件可能在全文里，不能只读要点就当作制度结论。

### 2. 改了检索参数，却不知道是否该发布

旧网页以“旧来源全部保留”判断候选。V7 改用实际问答入口，在同一套已标注开发题和相关历史任务上比较；展示原策略/候选节选，记录完整配对结果。删除弱相关片段不再天然失败。通过代表检查项没有回归，不代表语义一定更好。

候选绑定配置、资料、样本、评测器和基线版本。来源停用或正文变化，不能沿用旧结果直接发布。人工看完后明确确认；发布前重新检查。只有当前策略可以回滚，恢复其真实前一版本。

### 3. 参数改了，旧结果和确认却可能留下

工具保存任务ID、输入版本、请求版本、输入与结果指纹、状态和确认记录。改参数后清除旧结果和确认；执行期间修改输入会丢弃迟到结果；生成Word期间改动也停止旧文件。返回不完整或检查不通过的结果不能确认交付。

## 怎样操作

**资料问答**：自动路由或选择工作流 → 提问 → 看原文要点 → 展开依据 → 必要时补资料或查看工具。需要模型草稿时，只有部署者配置了接口、你明确许可，才发送本轮问题与片段。

**业务任务**：选择工具 → 在具名字段或高级JSON里确认输入 → 执行 → 看结果和异常 → 勾选并确认当前版 → 导出CSV/JSON/Word。八类工具沿用原计算函数；不是会自动操作真实业务系统的Agent。

**反馈运营**：同一任务选择已解决、未解决或需要复核。进一步填写具体问题；资料缺口转待办，意图/生成问题转复核，不用增加top-k冒充修复。检索类问题才形成受限参数候选，人工审核后本地生效。

**隐私与作用域**：本地状态不共享给其他访客，也不是角色权限系统。刷新后保留IndexedDB数据，清空浏览器数据会删除它们；工作区导出可用于自己备份，注意不要公开私人原文。用户关闭任务不等于策略已发布，策略发布也不等于某份业务材料已获审批。

## 还没有完成

真实模型多任务端到端质量评估、企业多用户审批、跨服务原子发布、跨重启持久后台作业、真正的工具链依赖调度、线上灰度实验均未在本轮宣称完成。当前是八类单工具任务使用统一生命周期，并非任意任务自动规划执行。下一步应先验证真实模型与实际任务，再扩基础设施。
