# 金枢｜可投递项目表述

个人项目｜基于既有文枢工程的产品与业务适配，AI辅助工程实现。不是两人协作项目，除非确有另一位参与者；不虚构团队分工。

## 单项目版（4条）

**金枢｜金融中后台知识与业务辅助 Agent**　2026.08—至今

- **产品与编排：**围绕知识查询、发行支持和核查辅助设计业务流程，明确模型、确定性工具与人工复核边界；保留可信RAG与反馈迭代，新增周报质检、同业对标的依赖编排和复核包。
- **知识与策略运营：**按来源、版本和生效状态维护资料，结合BM25、中文语义向量和RRF检索，支持引用回查；将反馈转为受限检索/表达候选，经历史回放和独立审核后灰度发布、支持回滚。
- **可靠执行与业务交付：**为8类工具增加请求防重、服务器检查点与输入版本，支持中断后请求恢复、局部重试和结果复用；补充日历范围与排期冲突校验，输入变更后旧审批失效，经独立复核导出JSON/CSV草稿。
- **验收与运营观测：**记录步骤耗时、失败原因、执行尝试和复核状态，使用合成数据覆盖重复请求、并发旧结果、进程中断恢复、权限隔离及导出校验；将程序回归、真实接口连通与用户业务效果分开验收。

## 空间更紧时（3条）

- **产品与知识运营：**基于既有Agent工程适配金融中后台场景，结合BM25/语义检索、资料版本和独立审核，提供原文引用、反馈归因及受限策略回放发布。
- **业务流程与交付：**将理财对标、排期、周报等8类工具接入受控流程，新增输入门控、检查点和请求防重；支持局部重试、版本复核及JSON/CSV导出，减少重复执行，拦截过期确认。
- **验证与复盘：**以合成用例验证重发、并发、进程中断及日历冲突，记录节点耗时与失败原因；区分代码验收、模型连通和真实业务效果，不以测试通过率替代业务正确率。

## 暂时不写

没有借用差旅V2的91%、86%、13.4秒、Recall/MRR数据。没有说“自主训练”“金融机构生产上线”“数百真实用户”“严格不丢不重”“全量日志回流”。默认网页使用的向量和可选Milvus不能混写成同一条已实测链路。K8s/HPA/pi-durable/CP-SAT未在本轮运行验收，不作为新成果。

测试数量由最终CI证据更新；不要继续把旧500项开发集当新版实测。源代码中已存在的能力与个人新增适配分别解释。
