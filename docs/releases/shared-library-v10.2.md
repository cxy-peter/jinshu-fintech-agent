# V10.2：恢复共享资料版本与登录后自动检索

V10.1 恢复的资料只在本机浏览器保存，其他网站用户仍然只看到原有的一份演示资料。V10.2 增加独立的共享学习资料库，用户明确授权恢复的原文进入服务端持久化存储，登录后可以浏览目录、逐页阅读和自动检索。

## 数据边界

- 原文件和本机恢复包保持不变；资料正文不进入公开 Git、Vercel 部署包或前端静态资源。
- MongoDB 使用 `jinshu.reference_library` 保存压缩版本、目录和当前版本指针；本地对应 `references.sqlite`。既有 `governed_state` 和审核记录不变。
- 新库避免将大资料包塞入原有 8 MB 状态快照；原有机构制度审核仍独立执行。
- 恢复的资料标为 `active_reference` / `shared_reference`，是所有者授权的学习参考，不伪造独立审核人或现行制度效力。
- 未登录只显示数量提示。目录详情、原文页码、检索接口、问答检索均校验登录。API 响应为 `no-store`。

## 恢复与核验

`scripts/restore_reference_library.py` 使用编辑账号向认证 API 分片上传，凭据通过 `JINSHU_IMPORT_PASSWORD` 环境变量或交互输入提供。必须显式传入 `--share-with-logged-in-users`。公开演示账号适用于已获共享授权的研究材料，不适用于机构秘密资料。

服务端核对分片长度、完整包 SHA-256、解压大小、唯一文档 ID、真实页码、预计文件数与页数，全部通过后才原子切换目录指针。并发版本冲突拒绝覆盖，重复提交同一版本保持幂等。MongoDB 临时上传分片在 24 小时后自动过期；已发布档案保留。

## 检索与阅读

按原页码复用既有条款/表格切片逻辑，构建页级 BM25 倒排索引；覆盖度不足不召回。旧有已审核资料的 BGE 语义检索继续保留。新增大资料库当前不宣称已完成向量索引或 Milvus 导入。

问答默认同时检索可用共享来源，引用携带文档 ID、原页码、片段哈希和恢复版本。回答完成后再次检查登录与版本，避免输出已经失效的权限或版本。点击引用可打开共享原文页；目录可导出。

## 验收范围

- 82 项后端测试，包括认证隔离、跨账号/进程读取、真实页码、自动 RAG、共享确认、错包拒绝、版本竞争和只读保护。
- 37 项 Node 检查通过，Windows 符号链接检查因权限跳过。
- 完整本机恢复包已通过真实 HTTP 导入：93 份、3790 页、压缩后 3146218 bytes；目录 ID 与源包逐项一致。
- 云端最终发布与数据导入结果另以本次执行证据为准，不将本机结果写作线上成功。

历史研报用于研究学习；扫描图、金融表格布局和公式仍需对照原文件。资料未覆盖的正式发行排期制度不能由合成示例冒充。
