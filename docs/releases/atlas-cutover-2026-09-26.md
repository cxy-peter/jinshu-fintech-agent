# Atlas 免费集群迁移验收 · 2026-09-26

金枢与 Visit China 已从私有 Blob 切换到同一 Atlas Free 集群内的两个独立数据库。网页和 API 继续部署在 Vercel；公开评测档案在 GitHub；没有购买数据库服务，也没有把私有记录上传至仓库。

## 实际操作与核对

1. 为两个应用创建独立随机凭据，仅授予各自数据库 readWrite，并限制到目标集群。实测双方读取另一个库均被拒绝。
2. 用户明确授权后，添加所有 IPv4 的网络访问规则以适配 Vercel 动态出口；仍强制 TLS 和密码认证。这不是 IP 隔离方案，不应直接套用到需要固定出口的机构环境。
3. 两个线上应用先以原 Blob 后端进入只读；确认拒绝写入，等待旧请求结束，复查状态版本稳定。
4. 导出私有备份；向空目标导入；逐项目核对完整内容 SHA256 和各类记录数。已有目标不覆盖。
5. 保持只读部署 MongoDB 版本，确认线上读取原资料和后台目录，再恢复写入并重新部署。
6. 验证真实 DeepSeek、权限、会话持久化及反馈；复查原 Blob 与备份完全相同。测试会话和反馈已清理；Visit China 空事件批次没有增加虚构转化。

## 容量与恢复边界

导入的两个BSON状态文档合计816,612字节，约0.8MB，不含索引。Atlas原有样例数据保留。512MB免费容量足够当前低流量演示，但本应用仍有单状态8MB上限和资料/会话数限制；没有因接入数据库自动取消这些边界。

本地保留迁移备份，原Blob保留迁移时状态；免费Atlas没有启用托管自动备份。此处不是宣称已经配置持续备份任务。新写入后若要回滚，须先冻结Mongo并导出新增记录，不能直接切回旧快照。旧部署URL不作为正式入口，使用稳定生产域名。

连接串仅配置在对应Vercel Production敏感环境变量中，未写入前端、GitHub或此报告。DeepSeek仍使用原有API账号计费；没有额外购买Embedding、Redis、Milvus或pi服务。
