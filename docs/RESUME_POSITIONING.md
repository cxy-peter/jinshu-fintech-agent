# 一个项目怎样连接两段实习

## 放在简历哪里
独立放在“个人项目”，不要塞进Bitget或施罗德的实习成果。来源是两段经历中的问题与已有程序，而不是两家公司共同委托了这套系统。

## 统一业务场景
金融产品中后台人员收到查询或材料任务，需要找对规则、调用已有程序、生成可复核交付物，再把重复失败沉淀为可回放的改进。客服、风控产品和理财运营共享Harness、知识、Memory和Loop，但部门资料与业务工具不混用。

## 标题
金枢｜金融产品中后台自进化Agent（实习场景延伸的个人项目）　2026.09—至今

- 业务与工具：结合理财对标、发行排期及客服核查需求，适配原Agent工程，组织9类中后台工作流；将既有Python方法封装为参数化Skill，生成对标结果、排期及Word材料草稿。
- 知识与流程：沿用Harness/DAG、分层Memory和混合检索，补充8份模拟PDF的解析、表格切片、审核发布与来源回查；支持上传者敏感标记和审核人分级授权。
- 反馈迭代：跑通反馈归因、受限候选、20条历史配对回放及审核灰度；验证查询、top-k与模板改变，补充回滚接口失败时的稳定基线回退，保留执行与策略记录。

## 一分钟讲法
我在两段实习中接触过客服知识与流程需求，也做过理财产品数据和材料处理。我发现这些工作不只是回答一个问题，还要找对应版本、执行计算、整理材料并留下待确认事项。所以我基于已有Python方法和参考Agent工程做了金枢原型。它把任务、知识与工具连接起来，并用真实执行记录验证反馈是否改变了下一次检索，而不是只收集点踩。目前数据为模拟，验证是本地流程，不是公司生产上线。
