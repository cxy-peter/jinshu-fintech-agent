## 为什么恢复

V9 为解决 DeepSeek 登录与部署问题，默认只启动对话和八类工具。V7/V8 的原代码仍在，但资料、记忆、审核、Loop 没有接到默认网页。这次采用加法恢复，不替换 `jinshu/`、`engine/`、`unified/` 原企业实现。

## 资料链路与旧补丁

提交正文 → 按标题/条款切片、表格按完整行重复表头 → BGE-small-zh 512维语义向量 → 独立审核 → 生效版本原文 → BM25与语义检索 → RRF → 条款覆盖重排（可选 DeepSeek 候选重排）→ DeepSeek → 引用编号检查 → 再核对有效期、权限、版本、原文哈希 → 持久化 Trace。

模型固定版本 `Xenova/bge-small-zh-v1.5@75c43b069aac4d136ba6bc1122f995fedcfd2781`，ONNX int8 约24MB，构建时下载并核验SHA256。不是哈希向量或假Embedding。未下载或失败明确退回 BM25。模型权重不放 GitHub，也不上传私人文档到模型仓库。

保留了旧系统的重要约束：草稿不能召回；旧版本归档；向量库只返回候选ID并从有效原文回填；表格不从中间拆行；模型不执行资金/冻结/发信等操作；跨站写入拒绝；错误码区分；模型外部调用需同意；停止/切换对话不展示迟到回答；工具修改输入需要重新复核。

引用存在不等于事实正确。记录中的重排分数不是“置信度百分比”。无资料时可以一般解释，但不能伪装成机构政策。

## Loop 和 Graph 的边界

反馈 → 人工分类/目标资料标注 → 受限 Skill 参数（扩展词/top-k/结构）→ 回放 → 另一账号审核 → 5% → 根据两组明确反馈人工扩至20/50/100%，低质量护栏自动停用。知识缺口必须补正文并审核，不能用策略编造事实。资料、候选或样本变更使旧回放绑定失效。

当前配对回放是关键词召回回归，至少三条是流程准入，不是统计显著性。模型质量仍需人工样本验证；不宣称完成权重训练或线上准确率提升。Graph 展示资料、版本、条款、引用关系，未部署 Neo4j。

## 存储与免费接入

- 本地 SQLite：事务持久化；CPU BGE 无外部 Embedding 费用。
- Atlas：显式 `JINSHU_STORE=mongo`；独立库 `jinshu`。用户尚未创建账号，本轮只是准备好适配器与迁移工具。
- 当前私有 Blob：兼容已有云部署，条件写入防止多实例覆盖。Atlas 验收前保留。不是将私有资料放到公开 GitHub。
- Redis：配置 `REDIS_ADDR`；只缓存已授权当前会话，TTL30分钟，必须与持久化历史一致，失败退回持久化历史。
- Milvus/Zilliz：配置 `MILVUS_URI`、`MILVUS_TOKEN`；运行 `python scripts/setup_milvus.py` 创建512维COSINE集合并索引已有资料。失败仍可本地语义检索。尚未云端连通验收。
- 原 pi：`engine/services/pi-agent` 保留；单独启动并设 `PI_AGENT_ENABLED=true`、`PI_AGENT_URL`、`INTERNAL_API_TOKEN`。默认只使用受限查询改写，无业务工具权限；不会假装它已运行。

免费额度来源：[Atlas](https://www.mongodb.com/docs/atlas/tutorial/deploy-free-tier-cluster/)、[Upstash Redis](https://upstash.com/pricing/redis)、[Zilliz](https://docs.zilliz.com/docs/free-trials)。本项目未购买服务，免费额度可能调整。DeepSeek 推理仍按用户已有账号计费。

## Atlas 配置与迁移

1. 在 [Atlas](https://cloud.mongodb.com/) 创建 Free/M0 集群。金枢与 Visit China 可共用免费集群，用不同数据库用户分别授予 `jinshu` 和 `visit_china` 的 readWrite 权限。连接串只配服务端，不发聊天。
2. 设置 Network Access：测试先允许本机IP。Vercel动态出站需要允许部署出站网络；若采用全IP访问，必须用TLS、独立强密码及最小库权限。不要仅凭配置存在声称已连通。
3. 在旧部署设 `JINSHU_STORE_READ_ONLY=1` 并部署，等待旧实例写入结束。保持旧后端。
4. 可信本机加载旧Blob环境，运行 `python scripts/migrate_store.py export workspace/private/jinshu-backup.json`。文件私有；不能进仓库。工具拒绝覆盖已有备份。
5. 本机增加 `MONGODB_URI` 和 `MONGODB_DB=jinshu`，运行同一工具 `import`，再 `verify`。目标非空拒绝导入，核对记录数与内容SHA256。环境变量需先加载到进程；脚本不输出密钥或原文。
6. 线上设置 `JINSHU_STORE=mongo`、上述URI和库名，仍保持只读；重新部署，验证历史/资料/权限。
7. 验证后取消只读并部署。旧 Blob 不自动删除。开放新写入前可切回旧后端；开放后回滚必须先冻结并导出新数据，不能直接退到旧快照。

原型使用单状态文档CAS，上限8MB、80资料/100会话/200反馈，不等于Atlas容量上限。高并发和更多数据需拆集合/审计归档，不能把数据库免费容量当本原型已实现规模。
